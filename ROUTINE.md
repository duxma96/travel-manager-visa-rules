You maintain the public visa data for the Travel Manager 90-180 Android app, in this repository (duxma96/travel-manager-visa-rules). Read README.md first. The app downloads `rules/<passport>.json` (rules for one passport) and `visa-types.json` (every visa type each destination issues, the same for every passport). A wrong rule can make a traveller overstay, so accuracy beats coverage.

NEVER push to main. All changes go through a pull request that the owner (Dusan) reviews.

Do the whole run. A complete run takes a long time (many pages to read) — keep going until both quotas below are met or nothing is left; do NOT stop after a partial batch to report. Only stop early if official sites are unreachable, and say which.

Steps:

0. Branch: if an open pull request from a previous run of this task exists (branch name starting with `visa-rules-update`), check out that branch, merge `origin/main` into it (on conflicts in generated files — `rules/*`, `all.json`, `index.json`, `visa-types.json` — keep either side and rebuild in step 4), and continue it (add commits, update its description). Otherwise create a new branch `visa-rules-update-<YYYY-MM-DD>` from main.

1. Refresh the base data: `node build.mjs --fresh` (downloads the latest passport-index-data CSV; MIT licence in THIRD_PARTY_LICENSE). Note: the SCHENGEN zone rule (90 days in any 180) is generated by build.mjs for every non-EU passport — it is intentionally NOT in overrides.json; do not add it.

2. Visa type catalogue (do this first). `visa-types/<CC>.json` holds, per destination, EVERY visa type and entry permission it issues (visits, business, transit, study, work, family, residence, permanent residence, visa-free entry, travel authorisations). README.md lists the destinations still to do. Each run: add at least 5 and up to 15 destinations still missing (in the README's order, then any other country; skip one whose official site does not answer and note it), fill `who` for existing types that lack it, and re-check types whose `checked` date is older than 6 months. Use only the destination's official immigration, interior or foreign-affairs sites. Follow the format of the existing files exactly (e.g. `visa-types/US.json`):
   - `id` (letters, digits, `.`, `_`, `-`; unique per destination), `name` (official English name), `category` (`tourist`, `business`, `transit`, `student`, `work`, `family`, `residence`, `immigrant`, `other`), `purpose` (one sentence: what it is for)
   - `who`: who can apply, short (e.g. "Anyone", "Citizens of Visa Waiver countries", "Spouses of citizens")
   - `limits`: how long you may STAY AT ONCE or in total (`{"kind":"stay","days":N}`, `{"kind":"year","days":N}` or `{"kind":"rolling","days":N,"window":M}` — see step 3) — only when an official page states a day count; `[]` for work, study and residence permits whose stay is the permit's validity
   - `maxValidity`: how long the visa/permit can be valid, short text, information only
   - `entries` (`single`, `multiple`, `varies`, optional), `note` (optional), `approx: true` when the day count is set at the border or not exact
   - `src`: the official page for that type (https), `apply` (optional, https), `checked`: today's date
   Leave a type out rather than guess. Then run `node build-types.mjs` (validates every file and builds `visa-types.json`) and `node check-links.mjs`: fix every link it reports as BROKEN; list the "blocked, check by hand" links in the PR.

3. Passport rules. Read `passports.json`: it lists the passports researched in depth (do not edit it). For EACH passport there, research how days are counted for every destination country in the world, as `overrides.json` → `<PASSPORT>` → `<ISO2>`. Skip the passport's own country, Kosovo (XK, treated as Serbia) and the Schengen member countries (one zone, see above). Work in a batch of about 60 destinations per run in total, shared between the passports: first destinations not yet present for a passport (alphabetical by ISO code), then re-check entries with the oldest `checked` date.
   Sources, in this order:
   a) The passport country's own foreign ministry travel page for that destination — `passports.json` gives its URL pattern in `mfa` when known.
   b) The destination country's own government, immigration or embassy website.
   Open pages with WebFetch. If WebFetch is blocked for a site, use WebSearch restricted to that official domain (allowed_domains) and rely only on results whose URL is on that official domain; cite that URL. Do NOT use blogs, travel agencies, airlines or Wikipedia as the source.
   Each entry has exactly these fields:
   - `req`: one of `free` (no visa), `arrival` (visa on arrival), `evisa`, `eta` (electronic travel authorisation), `required` (visa in advance), `banned`
   - `limits`: list of `{"kind":"stay","days":N}` (N days per continuous stay), `{"kind":"year","days":N}` (N days per calendar year) or `{"kind":"rolling","days":N,"window":M}` (N days in any M days). Use several limits when several apply. If the rule says "N days within 6 months from first entry", use rolling N/180 (the stricter reading) and say so in the note. Use [] when no day count applies or it is not stated.
   - `passportDays`: minimum passport validity after entry in days, only if the source states it
   - `note`: one plain English sentence a traveller understands
   - `src`: the exact official URL you used
   - `checked`: today's date YYYY-MM-DD
   If you cannot verify a destination from an official source, leave it out (do not guess) and list it as unverified in the PR.
   Keep overrides.json valid JSON, 2-space indented, sorted by passport then ISO code.

4. Rebuild: `node build.mjs` and `node build-types.mjs`. Check `node -e "for (const f of ['rules/rs.json','visa-types.json']) JSON.parse(require('fs').readFileSync(f,'utf8'))"` succeeds. Update the README's list of catalogue destinations still to do.

5. Commit and open (or update) the pull request titled `Visa rules update <YYYY-MM-DD>`. The description must contain:
   - per passport: a table of every destination added or changed with before → after (req and limits) and the source link; destinations you could not verify; how many destinations are still missing;
   - catalogue: destinations added, types changed (before → after for day limits), links to check by hand, destinations still to do;
   - anything that looked contradictory between sources.
   If no official source at all is reachable (network blocked), stop: open no PR and say exactly which domains were blocked. Do not merge the PR.
